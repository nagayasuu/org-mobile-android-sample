# 比較実験の固定入力を事前照合する

モデルを呼ぶ前に、公開可能な合成入力と既存の受け入れ条件から照合計画を作る。Python 3.10以上・Git・標準ライブラリだけを使い、ネットワークやモデルは呼ばない。入力の完全性を調べる補助であり、課題の妥当性やモデル回答の正しさは既存の検証・レビューで判断する。

## 計画を固定する

次のJSONを `.local/` の実験用ディレクトリへ保存する。パスは `--root` で指定する実験コピーからの相対パス。`revision` はそのコピーの `git rev-parse HEAD`、各 `sha256` はファイルの生バイト全体のSHA-256である。未コミットの候補版は対象SHAに加え `files` で内容を固定する。プロンプト生成・抽出に使うツール、手順、関連入力も `files` に列挙する。空の `files` は追加対象がない場合だけ使う。

```json
{
  "schema_version": 1,
  "revision": "<40桁の対象コミットSHA>",
  "prompt": {"path": "input/prompt.txt", "sha256": "<64桁>"},
  "snippets": [
    {
      "path": "input/source.kt", "sha256": "<原文全体の64桁>",
      "start_line": 1, "end_line": 4,
      "snippet_sha256": "<対象行の生バイトの64桁>"
    }
  ],
  "operations": ["取消後の本文を保持する"],
  "assertions": ["assertEquals(\"本文\", actual)"],
  "files": []
}
```

範囲は1始まり・両端を含む。UTF-8原文を改行を保って切り出し、そのハッシュとプロンプトへの完全一致の包含を確認する。プロンプトと必要断片は空白だけでは不可で、末尾に改行が必要。原文・プロンプトは改行を正規化せず固定する。JSON文字列にエスケープして埋める方式は対象外であり、モデルへ渡すテキスト内に原文をそのまま含める。

`operations` は対象操作を示す文字列、`assertions` は維持すべき既存アサーションの文字列をそれぞれ一つ以上指定する。空文字は不可。両者をプロンプト内で照合し、アサーションは必要断片内にも存在することを確かめる。必要な全操作・全アサーションが列挙されているかは人またはレビュー担当が原文と照合する。単語の存在だけで意味の妥当性を認定しない。

不備の再現では正常入力から一要因ずつ、末尾改行を落とす、抽出範囲を空にする、断片・操作・アサーションを取り除く、版・ハッシュを変える。入力のハッシュを更新しても内容上の不備で拒否されることを確認する。既知の失敗群は残し、修正群は別版にする。失敗を通すために照合条件や正解を緩めない。

## 実行と記録

実験コピーの編集と入力生成を終え、計画を別途レビューして固定してから、各モデル呼出しの直前に実行する。

```sh
python3 scripts/check_trial_input.py .local/experiment/input-plan.json --root .
```

成功時は終了コード0、失敗時は1。JSONは `ok`、失敗時の `error` と `check_seconds` のみを返し、原文やパスを出力しない。エラーコードの対象は計画・ローカル原文で調べる。後続の実験コマンドは成功した場合だけ開始する（シェルでは `&&` で接続する）。このツール自体は実験を起動しない。照合後に入力を変更せず、同じファイルをモデルへ渡す。呼出しまでの変更を原子的に防ぐ仕組みはない。

照合計画と結果を `.local/` に保存し、計画自身のSHA-256も台帳へ記す。生結果の保存には[試行の記録手順](trial-measurement.md)を使い、既存の失敗を上書きしない。集約記録には検出した不備数、正常入力の誤拒否数、計画準備時間、照合時間、入力不備による無効なモデル試行数を分けて残す。未取得値は未計測。ローカルの計画・原文・パスは公開せず、公開可能な合成例と集約値だけを共有する。

自動テスト：`python3 -m unittest discover -s scripts/tests -p test_check_trial_input.py -q`。初期の評価結果と限界は[CA-003の評価記録](../records/evaluations/2026-11-15-ca003-input-check.md)を参照する。
