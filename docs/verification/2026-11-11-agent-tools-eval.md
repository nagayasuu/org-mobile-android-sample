## 比較条件

対象は `chore/agent-context-followup` の[実装と受け入れ条件](2026-11-11-agent-tools.md)。ユーザーから比較測定、追加改善の調査、未確認事項の解消、コミット・PR・CI・統合を順に進める依頼を受けた。

公開追跡ファイルを基準版 `49783f5bcf67609b7a794a5b87920abc88e21b28` から一時リポジトリへ複製した。無関係な未追跡資料・個人設定・認証ファイルを複製しない。baseline は基準版、optimized は2つのCLI・追加テスト・更新した2手順書を適用した版。各課題の入力と開始状態を初期コミットで固定し、同じプロンプト・対象ファイルのハッシュを条件間で照合した。

環境は Linux、Python 3.13.16、Codex CLI 0.166.0、モデル `gpt-6.1-sol`、reasoning effort `high`。既存の ChatGPT ログインを利用し、新しい API キーは作成・使用していない。`codex exec --json --ephemeral --sandbox workspace-write` で独立したセッションを実行した。基準版と改善版のモデル・設定は同一。実行順は文書baseline→文書optimized→変更optimized→変更baseline→境界baseline→境界optimized。

確認できた厳格成功は baseline 1件、optimized 0件、各条件1件ずつ保留であり、保留を成功や分母からの除外として扱わない。利用者確認が適用可能であることと各実行が確認元を読んで記録したことは分け、後から根拠を補って初回成功へ算入しない。baseline の別 agent 起動失敗の原因説明は agent の申告に基づき、外部検査で原因まで独立確認したとはしない。

結論：30%削減と成功率差3ポイント以内は達成確認できなかった。失敗・不明な結果も残し、個別課題の減少だけで全体の改善としない。次の比較では同じレビュー方式に固定し、子の使用量を別に収集してから反復する。

起動前の失敗：最初の文書baselineは、外側の読み取り専用制限により Codex 自身の状態を初期化できず終了1。モデルイベントと usage は出なかった。生ログを保持し、必要な実行権限を得た後に同じ入力で再実行した。この失敗を成功扱いや使用量ゼロとして集計しない。

外部検査側の修正：旧ソースへ一時復元する回帰テスト検査で、同サイズ・同秒の書き戻しにより古い `.pyc` が有効となる汚染が見つかった。成果物ソースの不具合とはせず、各テスト子プロセスに新しい `PYTHONPYCACHEPREFIX` を割り当てて再確認した。復元後のソース・ハッシュを保持し、対象モジュールの汚染キャッシュも除いた。評価対象のモデル実行結果を改変したり、モデルを成功するまで再実行したりしていない。

## 追加改善の調査

ローカルCLIの有効な設定から、MCPサーバーの登録とプラグインの明示設定はともに0件だった。設定ファイルや接続先・個人情報は公開記録へ転載しない。ローカルCLIで不要なMCPを無効化する追加変更は根拠がないため行わない。ChatGPT Work の接続ツール構成とは別であり、そのツール定義のトークン数を測定したとは扱わない。

レビュー担当は親会話なしの依頼から今回の実装・計測設計を確認した。独立セッションの使用で引き継ぎを小さくできることは確認したが、親会話継承との使用量比較はまだ行っていない。設定を変更する前に、課題実行の結果から追加調査の必要性を判断する。

文書課題で見つかった R12 の誤判定を受け、開発手順のレビュー節に適用範囲と根拠の継承方法を補足し、依頼文へ共有範囲・利用条件の根拠を渡す欄を追加した。R01〜R30の本文・必須検証は変更しない。この補足は予備比較の optimized スナップショットには含めず、追加の品質改善として扱う。

コード課題では別レビューの実施記録がある一方、CLI の JSONL に子の識別子・実行履歴・使用量を追跡する情報が不足した。親の値を全 agent の総入力として扱わず、確認者の選択や実行形態をそろえて評価することを正本へ明記した。既存の `--ephemeral` 実行に対応する永続メタデータもなく、取得不能分をゼロとして埋めていない。
