## 設定と判断

[Android の公式手順](https://developer.android.com/studio/test/coverage-report)の
`enableUnitTestCoverage`、`testCoverage.jacocoVersion`、
`createDebugUnitTestCoverageReport` を採用した。
[Gradle の JaCoCo 設定](https://docs.gradle.org/current/userguide/jacoco_plugin.html)と
[JaCoCo の変更履歴](https://www.jacoco.org/jacoco/trunk/doc/changes.html)も参照した。
JaCoCo は [EPL-2.0](https://www.jacoco.org/jacoco/trunk/doc/license.html)で提供されるテスト用依存で、APK には含めない。

標準設定だけの初回レポートでは、Robolectric で実行した MainActivity・OrgAdapter・
ReaderViewModel が0%になった。`includeNoLocationClasses` を有効にし、アプリの
名前空間だけに計測を限定した結果、実際の実行が反映された。AGP のタスク拡張が
登録された後に設定する。調整中に Groovy の拡張解決による設定エラーも発生し、
実テストの失敗とは区別して修正した。セッション ID は固定し、端末名を記録しない。

除外は AGP 標準の生成コード・テスト・依存ライブラリのみ。アプリ実装・内部クラスを
除外する設定や閾値の引き下げは行っていない。XML 上の全5ソースファイルとアプリの
ソース一覧を照合し、カウンターを持たないインライン由来の `ActivityViewModelLazy.kt`
以外に依存ソースが集計されていないことを確認した。
