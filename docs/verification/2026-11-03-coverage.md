# カバレッジ計測の導入と検証

## 対象と受け入れ条件

- 依頼: README の項目1。アプリの動作は変更せず、Debug 全 JVM テストの
  JaCoCo 計測、HTML／XML、行・分岐80%以上と既存変更ソース群の低下判定を追加する。
- 対象: `48da0f4` を基準にした `build/jacoco-coverage` の未コミット差分。
  `app/build.gradle.kts`、`gradle/coverage.gradle`、`scripts/check_coverage.py`、
  `scripts/run_coverage.py`、`scripts/tests/test_coverage.py`、CI と関連文書。
- 計画: 既存テストの基準確認 → AGP 標準レポートで計測 → 判定と CI を追加 →
  失敗条件・基準側の再計測・共通検証 → 別 agent レビュー。
- 実行者: 作成 agent。環境: Temurin 17.0.21、Gradle 9.4.1、AGP 9.2.1、
  内蔵 Kotlin、SDK Platform 37.0／Build Tools 37.0.0、Robolectric 4.16。
  計測は JaCoCo 0.8.14 に固定した。版更新は別変更として検証する。
- Git: 作業ブランチ作成のみ。コミット・push・PR 作成・統合は行っていない。

## 設定と判断

[Android の公式手順](https://developer.android.com/studio/test/coverage-report)の
`enableUnitTestCoverage`、`testCoverage.jacocoVersion`、
`createDebugUnitTestCoverageReport` を採用した。
[Gradle の JaCoCo 設定](https://docs.gradle.org/current/userguide/jacoco_plugin.html)と
[JaCoCo の変更履歴](https://www.jacoco.org/jacoco/trunk/doc/changes.html)も参照した。
JaCoCo は [EPL-2.0](https://www.jacoco.org/jacoco/trunk/doc/license.html)で提供されるテスト用依存で、APK には含めない。

標準設定だけの初回レポートでは、Robolectric で実行した MainActivity・OrgAdapter・
ReaderViewModel が0%になった。`includeNoLocationClasses` を有効にし、アプリの
名前空間だけに計測を限定した結果、実際の実行が反映された。AGP のタスク拡張が
登録された後に設定する。調整中に Groovy の拡張解決による設定エラーも発生し、
実テストの失敗とは区別して修正した。セッション ID は固定し、端末名を記録しない。

除外は AGP 標準の生成コード・テスト・依存ライブラリのみ。アプリ実装・内部クラスを
除外する設定や閾値の引き下げは行っていない。XML 上の全5ソースファイルとアプリの
ソース一覧を照合し、カウンターを持たないインライン由来の `ActivityViewModelLazy.kt`
以外に依存ソースが集計されていないことを確認した。

## CI・端末・残る確認

- CI: `verify` に計測・判定を追加し、HTML／XML／比較結果は既存の `android-reports`
  へ含める。push・PR 作成は依頼されていないため、GitHub での実行と成果物取得は未確認。
  公開後に対象 SHA・run URL・成果物を照合し、閾値割れ・低下時の拒否も確認する。
- ブランチ保護: 既存記録では `verify` が必須。現在の GitHub 設定の再取得は未実施。
  ワークフロー変更だけで保護が有効と断定しない。
- 端末: 実行していない。アプリ実装・UI・SDK・実行時依存を変更せず、JaCoCo は
  テスト JVM 限定のため、この変更で端末操作は省略した。生成 APK の DEX に
  `org/jacoco` 参照が含まれないことを確認した。
- 比較条件: ビルド入力が異なる変更は自動で比較を止める。依存更新などを行うときは、
  同一条件を整えてから別途検証する。改名・削除は比較群に含めず、新規ファイルは
  全体の80%条件へ含める。ソースルート・名前空間変更時は設定を見直す。
- 時間: ローカルの同条件比較は各1回であり、統計的なオーバーヘッドは未確定。
  継続運用時に CI の実行時間を確認して記録する。担当は次に公開・統合する保守担当者。
- actionlint は利用環境になく未実施。ワークフローの静的差分確認を行い、実際の
  GitHub 実行で SDK の準備・比較元取得・成果物アップロードを確認する。
