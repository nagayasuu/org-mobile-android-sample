# コミットメッセージ検証と Git フックの確認

実施日：2026-11-02（日本時間）。対象：[PR #9](https://github.com/nagayasuu/org-mobile-android-sample/pull/9) のコミットメッセージ検証、Git フックと CI 定義。

## 対象と受け入れ条件

- 規定の種別・形式、1行目50文字、本文・フッター各行72文字、本文前の空行、破壊的変更の表記を検証する。
- ローカルの commit / amend で不正なメッセージを拒否し、ステージ済み差分の空白を確認する。
- 既存のフックを上書きせず、clone ごとに導入・更新・解除できる。
- フックを回避した不正コミットも PR 内の対象範囲から検出する。PR タイトルの編集でも再実行する。
- 必須ジョブ名 `verify` と既存のビルド・Lint・JVM テスト、APK・レポートの保存を維持する。
- README の実施状況と、Git 運用規約の実行手順を実際の結果へ合わせる。マージキューと並行保守用のブランチ運用は保留する。

## 保証の範囲と未確認事項

- Windows・GUI 経由のローカルフック動作は未確認。今回のローカル確認は Linux 上の Git / POSIX シェルで行った。
- ローカルフックは未導入や `--no-verify` で回避できるため、CI の検証と併用する。
- Squash merge 時に編集する最終メッセージは PR タイトル検証だけでは保証できない。統合前に確認し、統合後の実際のメッセージも `main` の push CI で検証する。
- 日本語表現、理由・移行方法の十分性、Issue 番号の実在はレビューで確認する。
- アプリの UI・実装・依存は変更していないため、端末でのスモークテストは今回の対象外。

日常の導入・更新・解除と手動確認は[Git 運用規約](../git-workflow.md#自動検証と-git-フック)、CI の構成は[ビルド・検証の手引き](../android-build.md#ci)を参照する。
