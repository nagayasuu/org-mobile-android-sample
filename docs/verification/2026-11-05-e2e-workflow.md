# 手動実機確認を E2E の作業フローへ集約（2026-11-05）

## 目的と対象

利用者へ削除する内容と影響を事前に説明し、「この方法で修正してください」の承認を受けて変更した。
利用経路の検証を E2E に集約し、手動の実機確認を開発工程・完了条件・報告欄から外す。
未対応の条件は自動化の課題として残す。既存の JVM・Robolectric・Lint は共通検証として維持する。

作成者は Codex。ブランチは `test/automatic-e2e`、Git の比較元は
`60e6d90fe7b80213c69775c5471714722fd9ea0a`。
着手時には[直前の E2E 導入](2026-11-05-e2e-tests.md)の未コミット差分があった。
今回の対象はその状態からの文書・skill・参照設定の変更であり、製品コード・テスト・ビルド・CI は変更していない。

| 対象 | 変更 |

APK の識別、公開入力、初期化・後片付け、非同期処理の条件待ち、結果・未実行事項の記録は E2E の手引きに維持すること。
自動化の対象外を確認済みと扱わず、過去の検証結果を書き換えないこと。

## 残る課題

Dropbox 保存・クラウド接続、空ファイル、同じファイルの更新後の再読み込み、1万行文書・性能、
TalkBack・文字と表示サイズ・明暗、実機固有の挙動は現在の E2E では未対応。
追加方針は[開発手順の一覧](../development-workflow.md#e2e-gaps)へ集約した。
保守担当者は該当する利用経路・表示・依存を変更するときに見直し、シナリオ追加後に結果を記録する。
主観的な使いやすさや音声の自然さを、通常の自動操作・ノード検査だけで確認済みとはしない。

コミット・push・PR 作成・マージは行っていない。
