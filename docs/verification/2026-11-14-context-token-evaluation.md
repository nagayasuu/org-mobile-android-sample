# 節取得・再利用の改善前後の入力トークン評価

## 実行前の計画

利用者の「最後まで順番に実施」の指示に従い、PR #34作成・対象CI成功・mainへのSquash merge・マージ後CI成功を確認してから測定する。[固定計画と全プロンプト](2026-11-14-context-token-protocol.json)に正解・版・順序・予算・採否・停止条件を記録した。

変更前はaf4002a、変更後は59239be。アプリの対象ソースは同一で、差分5ファイル（取得ツール・試験・運用・記録）一式の効果を比較する。個々のオプションだけの効果ではない。モデル・推論・出力指定・役割ごとのプロンプトは両条件で固定する。

文書・解析・画面層テストの3課題を、隔離した公開Gitアーカイブで修正・外部検証・独立レビューまで各条件2反復、計12枠・最大24モデル実行、各役割240秒で比較する。解析のprecheckは注入した不具合によるJUnitのRedを確認し、画面層テストは追加前のGreenを確認する。Gradleはホストが実行し、モデルは実行済み結果を確認する。検証ではタスクキャッシュを無効化・再実行して、JUnit/Lint XMLの鮮度を保つ。

reviewerも自身の返却記録だけを作れるようworkspace-writeを使うが、対象外ソース・検証記録・レポートの変更は許可せず、ホストが前後のハッシュを照合する。作者の返却記録をレビューで共有しない。原文・R01〜R30・既存アサーションと独立レビューを維持する。

全担当と失敗を含む入力トークン/成功数を主要指標とし、成功品質低下なし・入力10%以上減・完了時間中央値の悪化20%以内・全担当usage取得を条件に判定する。利用・実行・時間上限・usage欠測・追加モデル・プロトコル違反で後続のモデル実行を止める。失敗・未開始も残し、認証・課金・モデルを変えて回避しない。実費と外側の準備・最終レビューの消費は未計測として分ける。旧評価群とは合算しない。

キャッシュ状態とサービス遅延は未統制。順序を反転しても各2反復の限定的な比較であり、通常開発全体の改善を保証しない。優先度「低」の6項目は実施しない。

## 再開と記録の制約

初回は文書課題の両条件が成功した後、変更前の解析課題で作者の修正と80テストが成功し、レビュー開始時の利用上限で停止した。失敗レビューのusageは欠測のまま残す。利用者の再開指示で、同じモデル・設定・保存済みソースのレビューを1回だけ再実行し、作者と検証を再実行せず、元の失敗と分けた。

再開レビューは独立スレッドで承認・R01〜R30・turn.completedのusageを取得した。完了確認中に主担当が完了記録を途中状態で上書きしたため、生イベント・回答・公開ソースとの照合から記録を復元した。実行コマンドは読取だけであることも確認した。失われたプロセス終了コードと再開レビュー時間はnullとし、正常終了コードや所要時間を推定しない。記録復元に関する別agentの確認は、試行内レビューやusageの代替には数えない。

元の作者のusage・検証時間は元の試行に一度だけ計上し、再開試行には追加レビュー分だけを計上する。待機期間は未計測。元のusage欠測と再開時間欠測を成功によって補完せず、全体および解析課題の完全な削減率・時間基準の達成は判定しない。
