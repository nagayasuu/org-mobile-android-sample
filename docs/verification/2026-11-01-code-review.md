# 開発手順に基づくコード見直し（2026-11-01）

作業ツリー上の最新の [AGENTS.md](../../AGENTS.md)、[開発手順](../development-workflow.md)、[Git 運用規約](../git-workflow.md) と各参照先に基づく見直し。初回実装の記録とは分け、今回の変更と確認範囲を残す。

## 目的と受け入れ条件

現在の閲覧機能を保ちながら、読み込みの失敗・取り消しに関する保証を補い、解析と画面処理を責務ごとに整理する。

- 連続読み込みで、新しい文書の表示後にキャンセル済みの古い読み込みが失敗しても、文書・正常状態・保存 URI が変わらない。
- 不正 UTF-8 の選択で現在の文書を保持して再選択を案内し、正常な文書を選び直すと表示へ戻れる。
- 読み込み成功時と文字コードエラー時に入力ストリームを閉じ、表示名の取得成功時にカーソルを閉じる。表示名を取得できなくても本文は読める。
- 日本語、見出し、リスト、段落、対応外構文、リテラルブロック、長文の末尾、画面再作成・取り消し・再読み込みの既存動作を維持する。

保証する自動テストの範囲はアプリ内の解析・状態管理と Robolectric API 35 上の画面・合成プロバイダーとの連携とする。実際の標準ファイル選択、Dropbox、API 37 の表示・支援技術の動作は端末で別に確認する。

## 見直しと変更

| 対象 | 確認した責務と変更 |
| --- | --- |
| `OrgParser` / `OrgBlock` | Android 非依存を維持。一行の構文判定と段落・リテラルブロックの組み立てを分離。解析ごとの状態は非公開の補助クラス内に閉じる |
| `DocumentDecoder` / `ContentDocumentSource` | 厳密な UTF-8 デコードと Android の読み取り専用アクセスを維持。ストリーム・カーソルの解放と表示名取得失敗時のテストを追加 |
| `ReaderViewModel` | `DocumentSource` を介したバックグラウンド読み込みと、成功した URI の保存を維持。キャンセル済みの読み込みによるエラー状態の更新を防ぐ |
| `MainActivity` / `OrgAdapter` | 標準ファイル選択と状態の描画を維持。システムバー・Insets・一覧初期化・状態監視・描画を分け、行種別ごとの装飾を抽出 |
| ビルド・CI・リソース・公開サンプル | JDK・SDK・Gradle の固定値、共通検証コマンド、明示した成果物だけの保存、読み取り専用権限、バックアップ無効化、見出しのアクセシビリティ属性を確認。定義の変更なし |

既存の単一 APK 内の責務・依存方向を維持し、外部サービスやモジュールは追加していない。今回の内部整理と局所的な修正は、本記録へ理由と検証を残す。

### 連続読み込みの不具合

古い読み込みをキャンセルしても、同期的なプロバイダーの処理は戻るまで継続し、その後 `IOException` などを返す場合がある。従来は例外を受け取ると無条件で現在の状態をエラーへ更新していた。

新しい読み込みを先に成功させてから古い処理を失敗させるテストを追加し、修正前に「古い IOException によるエラー状態」のアサーションで失敗することを確認した。既存 19 件は成功、新規 1 件は失敗した。失敗表示の直前に coroutine が有効か確認する修正後は、`IOException`、`SecurityException`、`IllegalArgumentException` の各ケースで成功した。

テストでは2本のワーカースレッドと同期用のラッチで順序を制御し、各待機に5秒の上限を設けている。スレッドは終了時に解放する。構造整理前に追加テストを成功させ、その後はテストを固定して本番コードを変更した。

### リスクと保証の限界

- 状態整合性：古い処理が新しい表示をエラーへ変える影響を重視し、再現テストと修正を実施した。発生頻度の実測はない。
- プロバイダー停止：今回の対策は古い結果による状態更新を防ぐもので、同期読み込みの即時中断やタイムアウトを保証しない。停止・長時間待機の確認と、必要に応じたキャンセル方法の検討を後続に残す。
- 大容量文書：全文をメモリ上へ読み込む既存方式を維持する。長文の末尾表示テストは時間・メモリの保証と分け、性能条件は実測してから決める。
- 表示・支援技術：構造整理の後も画面テストは成功しているが、API 37 の実機、TalkBack、最大文字・表示サイズ、利用者による操作評価は今回未確認である。

## CI 生成 APK の実機確認（同日）

環境は USB 接続した Pixel 10a／Android 17（API 37）。agent が ADB と UI Automator の画面構造取得を用い、専用フォルダの公開サンプルと合成文書だけを操作した。

| 操作と期待結果 | 結果 |
| --- | --- |
| 標準ファイル選択から公開サンプルを開く | 成功。日本語の見出し・本文・箇条書き・番号付きリスト・末尾の本文を確認 |
| 1万項目の長文をスクロールする | 成功。通常の縦スワイプによる移動と、検証用の大きなスワイプを追加して `項目 10000` の表示を確認 |
| 長文の途中でファイル選択を取り消す | 成功。アプリへ戻った後の文書と表示行が操作前と一致 |
| 長文の途中で横向き・縦向きへ回転する | 成功。文書を保持し、縦向きへ戻した後の最初の表示項目も一致 |
| 不正 UTF-8 を選び、正常な文書を選び直す | 成功。現在の文書を保持してエラーを案内し、再選択後に正常表示へ復帰 |
| 空文書を開く | 成功。空文書の案内を表示 |
| 公開サンプルのコピーを更新して同じファイルを開く | 成功。更新した見出し・本文が表示され、古い見出しが残らない |

標準選択画面の「戻る」は、フォルダ階層を戻ってからアプリへ戻る場合があるため、実際にアプリへ復帰したことを確認して取り消しを判定した。ADB でコピーを更新した後は、端末確認手順のメディアスキャンで選択画面へ再認識させた。画面構造・画像・端末識別子は公開対象に含めていない。


文字・表示の確認では、表示サイズは元の設定のまま、通常の文字倍率と `font_scale=2.0` を使った。端末をダークモードにしてもアプリの明るい閲覧画面とシステムバーを判読でき、倍率2.0の縦横それぞれで本文・操作を確認した。横向きのエラー画面も、案内の全文と再選択ボタンを判読できた。本文は一覧内をスクロールして読む。最大の表示サイズへの変更は今回未確認である。

### ユーザーによる TalkBack の確認

同じ CI APK・端末の公開サンプル上で TalkBack 17.1.0.1003738110 を一時的に有効にした。文字・回転・明暗の設定は元へ戻した状態で、ユーザーへ見出し・本文の読み上げと「ファイルを開く」への移動、迷いや手助けの必要性を確認した。

ユーザーから「読めて、操作にも問題ありません」との報告を受けた。agent による音声の聴取や直接観察とは区別し、ユーザーの操作と報告による結果として記録する。普段の TalkBack 利用経験や詳細な操作列は未確認であり、支援技術に慣れた利用者による評価まで完了したとは扱わない。読み込み中・空文書・エラーの TalkBack 音声や、見出し移動機能の詳細は今回未確認である。
