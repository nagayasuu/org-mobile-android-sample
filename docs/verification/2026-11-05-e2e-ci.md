## CI 修正

比較元は上記統合コミット。対象は `.github/workflows/e2e.yml`、`docs/android-build.md`、
`ReaderE2eTest` の起動補助処理、本記録。
Ubuntu runner の udev ルール更新・trigger・権限検査を含むステップが失敗した。
ログにはコマンドごとの trace がなく、どのコマンドが終了1になったかは断定できない。
udev の適用待ちと権限設定の経路を単純化するため、既存の KVM デバイスへの直接の権限設定と読み書き検査へ変更する。
デバイスがない場合は明示して失敗する。ソフトウェア CPU へのフォールバックやテストのリトライで隠さない。
使い捨て runner だけの設定で、ローカル実機の権限を変更する手順ではない。

actionlint と `git diff --check` を実行する。E2E の入力・表示アサーション・タイムアウトは変更しない。
修正したブランチで手動 CI を実行し、3シナリオ、診断と APK の取得まで確認する。

KVM 修正後の [E2E](https://github.com/nagayasuu/org-mobile-android-sample/actions/runs/41914110953) では、
KVM 準備とエミュレーター起動は成功したが、3件とも `openPicker` のパッケージ名取得時に
`StaleObjectException` で失敗した。取得した `UiObject2` の画面ノードが切り替わるため、
対応パッケージの存在を条件で待ち、既知のパッケージ名の文字列を保持するよう修正した。
対象へ E2E テストの起動補助処理を追加する。表示の検証条件は維持する。

追加修正後に JDK 17・API 37 のローカルで `check assembleDebug`、テスト APK 生成、
`pixel2Api37DebugAndroidTest` を実行し、終了0、3件すべて成功した（全体1分20秒）。
この成功を修正後の GitHub CI の成功へ置き換えず、最新ブランチを改めて検証する。
