# 自動 E2E テストの導入（2026-11-05）

> 以下は導入時点の検証と判断の記録である。その後、[E2E へ集約する作業フロー](../../workflow/verification.md#e2e-gaps)へ変更し、実機の手動確認手順は廃止した。末尾の実機確認に関する後続方針は当時のものであり、現在の開発工程ではない。

## 対象・計画

作成者は Codex。比較元は `60e6d90`、作業ブランチは `test/automatic-e2e`。
README 項目5と開発手順の3シナリオを、実際の標準ファイル選択からアプリ表示まで自動化する。
製品コードは変更せず、テスト・依存・Managed Device・手動 CI・実行手順をそろえる。

1. 既存テストと環境を調査し、着手前の状態を記録する（V1）。
2. 公開サンプル・合成長文・不正 UTF-8 をテスト APK から Downloads に配置する。
   Espresso でアプリ内、UI Automator で本物の DocumentsUI を操作する。
3. 共通検証・テスト APK のコンパイル、API 37 の3シナリオを実行する（V2・V3）。
4. 手動 CI、レポート保存と手順を照合し、別 agent の R01〜R30 レビューを受ける。

受け入れ条件は日本語の見出し・本文・箇条書き・番号付きリスト、長文の末尾、
取り消しと実際の横向き回転後の行番号・上端位置の保持、エラー表示後の正常文書への復帰。
既存の閲覧機能と必須 `verify` は維持する。Dropbox、実機、性能測定は今回の自動化の範囲外。

## 採用条件と根拠

- [AndroidX Test 公式リリース](https://developer.android.com/jetpack/androidx/releases/test)：
  runner/core 1.7.0、ext.junit 1.3.0、Espresso 3.7.0。
- [UI Automator 公式リリース](https://developer.android.com/jetpack/androidx/releases/test-uiautomator)：2.4.0。
- [Managed Devices 公式手順](https://developer.android.com/studio/test/managed-devices)：
  AGP の `localDevices` とタスク。
- [エミュレーターの公式描画設定](https://developer.android.com/studio/run/emulator-acceleration)：
  `swangle` は ANGLE + SwiftShader の対応モード。従来の `swiftshader_indirect` は非推奨。
- SDK Manager の公式一覧で `system-images;android-37.0;google_apis;x86_64` revision 8 の提供を確認。
  API 37.0 の Google APIs 通常イメージを使用し、ページサイズと ABI を明示する。
- DocumentsUI のセレクターは
  [Android 17 の公式レイアウト](https://android.googlesource.com/platform/packages/apps/DocumentsUI/+/refs/heads/android17-release/res/layout/)
  と実行結果を照合する。Downloads の名前に限り en-US を前提とする。
- 追加依存は AndroidX Test（Apache-2.0）のテスト APK 用のみ。公開サンプルと生成文書を使い、
  私的なファイルやアカウントは使わない。新たな製品依存・権限・文書プロバイダーはない。

詳細な HTML/XML は `app/build/` の手引きに記載した出力先で確認する。
ローカルの生ログ・端末識別子・環境固有パスは公開対象に含めない。

各テスト終了時の PNG・UI 階層 XML 計6ファイルを追加出力から回収し、PNG の非空・解像度、
XML の解析と文書タイトルを確認した。回転テストの画面は1920×1080、ほかは1080×1920。
診断の保存失敗 warning はなかった。

最後の共通検証後の本体 APK は同じ hash である。テスト APK は再パッケージにより
`0a9390fd9a60042f1521074d83eef86dcbadbb384422751e1bb8fd4cb3c8175c` へ変わった。
V3 の対象と再生成物を区別する。テストソースは下記の最終 hash のまま変更していない。

AGP 9.2.1 は `testedAbi` の明示後も未指定の警告を出した。
実際の作成端末・システムイメージは x86_64 であり、この組み合わせで V3 が成功した。
AGP 10 へ更新するときはこの設定と端末作成結果を再確認する。

初期のビルド試行ではコンパイラーのないホスト JRE と設定の enum 名の誤りを修正した。
最初の Managed Device 起動は一時領域の容量不足で失敗し、エミュレーター診断ログから
userdata に7,372.80 MBが必要なことを確認した。空き容量のある Git 管理外の専用領域へ
SDK と AVD の保存先を移した。Emulator 37.2.13 の `swiftshader_indirect` は描画スレッドで
SIGSEGV（終了139）となり、`swangle` に変更した。
通常 AOSP revision 6 では `AdvancedProtectionService` が無効な feature flag を参照し、
system_server が起動を繰り返した。API 37 を維持し、標準ファイル選択を備える
Google APIs revision 8 へ切り替えた。
SDK 導入と Gradle の端末準備を重ねた試行でイメージが不完全になったため、
両方を止めて SDK Manager 単独で再導入した。以降はイメージ導入の完了後に実行する。
移動後の SDK をシンボリックリンクで指定した試行ではイメージ検索に失敗し、
`ANDROID_HOME` を実体パスにすると端末作成が進むことを確認した。
これらはアプリのシナリオの失敗や成功とは扱わない。
その後、Managed Device 上で3シナリオを初実行した結果は3件失敗だった。
失敗画面の XML で `text/plain` により `.org.txt` に改名されていることを確認したため、
入力の MIME を `application/octet-stream` に修正し、配置直後の名前の検査を追加した。
この修正前の失敗を残し、同じ条件の無変更リトライで成功したとは扱わない。
最初の失敗実行でも、各シナリオの PNG と UI 階層 XML が追加出力に回収されることを確認した。
MIME 修正後は保持・回転とエラー復帰が成功し、公開サンプルから長文への再選択だけが失敗した。
失敗 XML では選択画面に残っていたため、ナビゲーションの閉鎖と選択後の画面遷移を
条件待ちする修正を加えた。期待する本文・末尾・位置・エラーのアサーションは維持した。
既存動作への回帰テストの追加であり、製品の誤実装を作って Red にする変更は行っていない。
