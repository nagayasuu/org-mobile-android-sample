# E2E廃止とRobolectricへの検査移行

## 目的と受け入れ条件

利用者の「今は開発効率を優先してE2Eを全廃する」という指定に従い、端末上のテスト・実行器・専用CI・依存・Managed Device構成を削除する。アプリ本体の振る舞い、既存のJVMテスト、必須CI `verify`、Lint・カバレッジ基準は維持する。

起動・選択結果・取消・エラー復帰・回転・再読み込みの既存Robolectric検査を維持し、空文書、1万項目の末尾、拡大・横画面、タッチ領域、見出し属性、公開サンプルと同梱assetの一致をローカル検査へ移す。端末設定の保存・変更・復元はE2E実行基盤のための処理なので移さない。

実際のDocumentsUI操作、OSのURI権限付与、実プロバイダー、実OSの描画・イベント順、端末上の性能は未検証になる。利用者はこのトレードオフを開発効率優先で選択した。Robolectric成功を端末上の成功と扱わない。手動実機テストを代替の必須工程にしない。過去の検証記録は履歴として保持する。

## 対象と計画

基準HEADは `53a0a2e`。既存の未コミット変更は残タスク文書のチェックリスト追加であり、保持する。主担当Codexが変更・検証を行い、別agentが差分と検証結果をレビューする。コミット・push・PR・GitHub設定変更は依頼範囲に含まれない。

| 手順 | 対象・期待結果 | 検証 |
| --- | --- | --- |
| 着手前 | 既存画面テストの基準を確認 | MainActivityTestを実行 |
| 検査移行 | 既存動作を保ち不足するローカル検査を追加 | 対象Robolectricテスト、検出能力確認 |
| E2E廃止 | テスト・CI・実行器・依存と現行手順を整理 | 参照検査、Pythonテスト、文書・差分確認 |
| 完了前 | 共通検証と独立レビュー | check assembleDebug、R01〜R30、保守19項目 |

既存動作の検査移行なので、未実装の振る舞いを作るためのRedは設けない。検出能力の一時変更は回帰テストの成功と分けて記録する。製品コードは変更しないためカバレッジの比較対象ソースはない。通常の比較スクリプトでその判定を確認し、80%基準を維持する。Gradle構成変更前後の実行時間・削減率は比較しない。

## 検証結果

実行者は主担当Codex。JDK 17.0.21・Gradle 9.4.1・SDK 37.0、Robolectric 4.16 / API 35を使用。最初の起動はホームのGradleキャッシュ書込み制限、次の起動はJDKの親ディレクトリ指定でテスト開始前に失敗した。既存のJDK実体と許可されたキャッシュ書込みで解消した。環境失敗はテストのRedと扱わない。

| ID | 実行・対象 | 結果 |
| --- | --- | --- |
| V1 | 変更前 `:app:testDebugUnitTest --tests 'dev.orgmobile.reader.MainActivityTest' --rerun-tasks` | 成功。既存8件 |
| V2 | 移行後のMainActivityTest・OrgAdapterTest | 成功、計15件。公開サンプル全行・空文書・1万項目・取消/再作成の行とoffset・長い更新文書の先頭/末尾・文字倍率2倍の縦横/明暗4条件・48dp・見出し属性を確認 |
| V3 | 検出能力の一時変更 | 48dpを1dp、見出し属性を常時trueへ変え、強化後は2件とも意図したアサーションで失敗。原文へ復元済み |
| V4 | `python3 scripts/run_coverage.py --base-ref main` | 最終版で成功。clean後にDebug/Release各49件（計98件）、失敗・error・skipなし、Lintエラー/警告0・Hint8、APK生成成功。行216/219（98.63%）、分岐83/89（93.26%）で80%基準を満たす。比較対象製品ソースなし |
| V5 | レビュー担当自身の `python3 -m unittest discover -s scripts/tests -q` | 成功、139件・失敗0・skip6。任意Kotlin構文木環境の6件は未実行 |
| V6 | 文書検証・差分確認 | 追跡済み80文書532リンクと新規の本記録を別途確認して成功。git diff --check成功 |

移行中の初回はListItemの引数順の誤記によるコンパイル失敗があった。修正後には未確定レイアウトの参照と未接続Viewのノード取得で検査が失敗した。非同期更新を処理後に子・親レイアウトを再計測し、見出しはViewのisAccessibilityHeadingを検査する形へ修正した。製品コードの不具合とは扱わず、最終成功と失敗履歴を区別する。

初回の検出能力確認は見出し属性の誤りだけを検出した。文字自体の高さが48dp以上になる条件では、minimumHeightを小さくしても測定高さの検査だけでは失敗しなかった。短い内容でも48dpを確保する最低設定の検査を追加した。再変異では2件失敗したが、復元後の共通検証でもタッチ領域検査が失敗し、View.minimumHeightとTextView.minHeightの参照違いを確認した。TextView.minHeightへ修正後、再変異でタッチ領域・見出し属性の2件とも該当するアサーションで失敗し、原文復元後の最終共通検証では全98件が成功した。原文復元はfinallyで行い、app/src/mainの差分がないことを照合した。

最終Debug APK SHA-256：`57d739a0dea08cd36d582adfb7da4c667c16116110eb9cfbd100604c3697d90a`。検証時間は今回の環境・キャッシュ条件の結果であり、移行前後の短縮率として比較していない。

CIは未実行（push・PRは依頼範囲外）。端末上のE2Eは今回の指定により廃止済みで対象外。必須verify・Lint・カバレッジ基準は変更していない。

## 再検討条件

保守担当は、OS・実プロバイダーとの接続に由来する不具合報告、標準ファイル選択や権限方式の変更、一般配布への移行時に未検証範囲を見直す。E2Eの自動再導入や定期実行は設定しない。実行時間・安定性の改善幅は未計測。
