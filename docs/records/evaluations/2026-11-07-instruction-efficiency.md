- 同じ合成文書の誤字修正を、変更前後の指示を置いた一時リポジトリで実行し、検証・判定・使用量を比較する。

## 同じ作業による比較

公開資料と合成文書だけを入れた2つの一時リポジトリを用意し、独立した作成 agent へ同じ依頼を渡す。文書の「確認しましす」を「確認します」へ修正し、各版の skill と手順に従って文書検証とレビューを行い、判定と根拠を保存する。変更前には比較元の指示、変更後には今回の最終版の指示を配置する。

アカウント設定や生の会話ログ、ローカル専用ファイルは公開記録に含めない。集計する場合は使用量・読取回数などの非機密の数値だけを取り出し、作成 agent とレビュー agent を合算する。

両試行のモデルは `gpt-6.1-sol`、reasoning effort は `high`。親会話を引き継がない作成 agent に同じ依頼を渡した。変更前の子レビュー agent も同じモデルで実行した。集計は各 agent の最終 `total_token_usage` を一度ずつ合算した。入力にはキャッシュ入力を含み、出力に含まれる reasoning を再加算しない。

この1組では入出力合計が約58%減った。指示の選択読解・skill 短縮・確認者の選択を合わせた観測で、個別の寄与は分離していない。キャッシュ状態と生成のばらつきを統制した反復実験ではなく、費用の削減率や通常開発全体の削減率は示さない。計測準備・集計・本プロジェクトの変更作業・最終レビューの使用量は表に含めない。文書の再読回数は別途計測していない。

保守担当はこの範囲で採用し、次の同種作業で全 agent の使用量・切り詰め・手戻りを再確認する。意味・要件が変わる変更をセルフレビューへ誤分類した場合や、指摘・手戻りが増えた場合は確認者の条件を見直す。出力切り詰めは今回減らなかったため、実作業でも必要な節へ読み取りを絞る方針を継続する。
