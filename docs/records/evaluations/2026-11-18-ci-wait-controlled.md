# 同じ60秒の実CI待機での削減効果（2026-11-18）

## 実行前に固定した計画

[前回の計測](2026-11-18-ci-wait-live.md)は監視開始点と区間長が異なった。利用者の追加依頼に基づき、今回は同じ長さの実CI待機区間を比較する。

- 対象：既存run `44309405912`、公開済みコミット `a147f8c3d08365344361ae77e31bedb81fc84d3c` の `Android checks` を4回再実行する（予定attempt 4〜7）。コード・PR本文・設定を変更せず、未コミット文書を送らない。
- 順序と反復：短1→長1→長2→短2。短は `write_stdin(yield_time_ms=10000)`、長は50000。各2回で順序を反転する。外側 `functions.exec` は55000ms。主担当1名、同じ会話・モデル `gpt-6.1-sol`・推論 `medium`。モデルの追加起動は行わない。
- 等しくする区間：権限審査、CI再実行、run/attempt照合、監視起動を済ませてからusage開始を記録し、60秒の固定観測を開始する。60秒中にCIが終了した試行は区間不一致として保持し、その群の削減率は算出しない。期間中、主担当はこの観測セッションの待機と60秒以内の経過報告だけを行う。
- 監視：`run_check.py --progress-interval 60 --timeout 240 -- gh run watch ... --compact --exit-status --interval 5` を一度起動する。固定観測は60秒で終了するが、監視は同じプロセスで実CI完了まで継続し、終了情報を別ファイルへ保存する。後で同じattemptのSHA・run/verify成功・終了コードを照合する。固定観測の終了をCI成功とは扱わない。
- 応答・入力の範囲：usage開始スナップショットから、60秒の観測終了結果を受けた最初のモデル応答でusage終了を記録するまで。各試行に終了結果を処理する応答1回を含む。モデルの処理時間によりusage区間は60秒より長くなるため実測秒数も記載する。開始後の一意なresponse IDと各usageを集計し、同じ区間のモデルのツール要求数とも照合する。総入力はキャッシュ入力を含む。累積usageの二重加算はしない。
- 予算：4試行・CI再実行4回、各CI上限240秒、観測は各60秒、各試行のモデル待機呼出し最大12回、試行内の観測総入力合計500万トークン。失敗・区間不一致・上限到達でも自動追加試行を行わない。前回の2試行は別評価として保持する。
- 採用条件：全4試行で60秒中CIが継続、同一SHA・CI成功を確認でき、長い側の合計モデル応答数と総入力が短い側から各30%以上減少すること。実CIの最終ジョブ終了から監視結果の保存までは各15秒以内。新たな失敗情報欠落・圧縮があればその影響を調査し、単純な優位性を認定しない。
- 集計：各条件は合計120秒の実CI観測。削減率は `1 - 長い側合計 / 短い側合計`。全担当は試行内の主担当1名で、準備・承認・全CI完了後の照合・文書整理・独立レビューは試行外。全工程の削減率や実費へ拡大しない。会話の伸長・キャッシュ・ランナー差は順序反転で抑えるが完全には固定できず、2反復の限定観測とする。
- 検知：同じattemptの全ジョブの最終 `completed_at` から、監視終了を実行側で保存したUTCまでを比較する。runの正確な状態遷移時刻は取得できず、GitHub側の秒精度と時計差も含む。主担当への最終CI結果の報告は試行外なので、その遅れの削減率は求めない。
- 保存：数値スナップショット・対象CIの原データ・計測補助を `.local/measurement/ci-wait-controlled/` に保持し、確認した非機密な集約値だけを本書へ残す。セッション本文や他会話を収集しない。作成agentが実行、独立レビューagentが試行外で照合する。

V1（作成agent）：事前照合 `check_trial_input.py` は各試行前に成功。凍結した計画・補助スクリプトと内容ハッシュ、各試行のusage開始/終了・ツール返却・60秒観測・実CI監視終了・run/jobsをローカル保存した。usageの追加response IDは試行間でも重複せず、開始時の既存IDとも非重複。数値合計と、同じ時間区間のモデルのツール要求数が各試行で一致した。対象会話のusageと種別だけを読み、本文は集計しない。

## 判定と適用範囲

事前の採用条件を満たした。確認した実行基盤では、経過報告の期限に収まる50秒のセッション待機を使う手順を採用する。対象タスクについて、基盤での待機幅・実CI待機区間のモデル応答/入力削減・実CIの監視終了結果を確認できた。必須CI・検証・失敗情報を維持する既存監視は変更しない。

この削減率は**60秒のCI待機を各条件2回観測した区間**に限る。CI開始から完了報告までの全工程、準備・承認・記録・独立レビュー、別の会話長や他の基盤へ適用する削減率ではない。CIのジョブ所要時間が短くなったことや、実費が同率で減ることも示さない。各条件2回だけなのでp95・統計的有意差・広い母集団の削減率は主張しない。

検知時間は監視結果を実行側に保存した時刻までであり、主担当が最終CI結果を読み終える時刻は試行外。正確なrun状態遷移時刻とGitHub/ホスト間の時計差は未取得。この限界を残したうえで、計画した監視結果保持と15秒以内の取得は満たした。以前の合成評価と全CI区間の単発計測は独立の記録として保持する。

保守担当は次の3件の通常CI待機または2026-11末に、経過報告・失敗検出・待機応答・取得できる使用量を見直す。短いCIで待機回数差が出ない場合も保持し、効果が再現しない環境では待機幅を再確認する。全工程の改善を判断するときは、今回の比較準備・4回のCI・記録・レビューも含めた別の計測が必要である。
