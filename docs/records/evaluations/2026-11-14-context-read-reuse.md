# 必要節の一括取得と返却済み本文の再掲抑制

## 目的・対象・受け入れ条件

利用者の指示に従い、必要節をまとめて取得し、ツールの使い方の再確認と同じ担当への本文再掲を減らす。作成者は主担当Codex agent、基準はmainの `af4002a`、作業ブランチは `feat/context-read-reuse`。既存の無関係な下書きは対象外。優先度「低」の6施策、モデル設定、検証・レビュー基準は変更しない。

- `context --include PATH SECTION [SECTION ...]` で共通事項と作業別節をまとめ、同一文書の重複行を一度だけ返す。
- 任意のstate/readerで、同じ作業・同じ担当への返却済み範囲のみ省略する。新規範囲、ファイル変更、refreshでは必要な原文を返す。
- 初回の共通事項・R01〜R30、行番号・原文ハッシュを保持する。別担当・別作業は別記録を使う。
- 不正入力、欠落、曖昧な節、UTF-8不正、最終出力上限の失敗では本文なし・記録更新なし。標準出力失敗でも記録を進めない。
- 従来のstateなしcontext/read/checkを維持し、保存はGitルートの除外済み・未追跡の.local内だけにする。

## 実装と限界

公開手順は[開発手順](../../guides/agent-tools.md#document-tools)へ集約し、AGENTS.mdやskillへ本文を複製しない。固定見出しはツール内で検索し、未知の追加節だけ見出し検索する例を示す。通常操作は公開例を再利用し、引数エラー・版変更・例にない操作のときだけ使い方を追加確認する。

記録は返却の履歴であり、読了・理解・担当者の認証を証明しない。下流での出力切り詰めや文脈喪失は検知できないのでrefreshが必要。同じ記録を並列更新せず、新しい作業・agent・セッションでは新しい記録を使う。ファイル全体のSHAが変われば旧範囲を再利用しない。依存先の自動探索・検証結果の再利用・意味解析は行わない。

保存内容を一時ファイルへ準備し、本文の書出しとflushが成功した後に置換する。保存確定時のI/O障害は、本文が届いていても失敗として返し、古い記録を維持する。stdoutとファイルの二つをまたぐ一括トランザクションを保証するものではない。

## 比較計画（実行前に固定）

モデルを呼ばない機械的な取得比較を行う。比較前後とも同じ現在の公開文書を読み、ファイルの内容ハッシュを実行前後で照合する。ツール差だけを比べ、指示の変更による差とは混ぜない。

- 対照：基準HEADのdocument_tools.pyをローカルへ取り出し、context change、開発手順document-tools節、ビルド手引きcheck-output節の3コマンドで読む。
- 改善：新context changeに上記2節をincludeし、専用の新しいstate/readerで1コマンド取得する。
- 同じ取得を2回行い、対照計6コマンドと改善計2コマンドを比較。上限は各コマンド既定値、CLI実行は最大8回、エラーがあれば比較を止めて記録する。
- 両者の本文を文書別・行番号別に照合し、初回は原文の和集合が完全一致、改善の2回目は本文なしで要求範囲を示すことを確認する。必須R01〜R30を初回に保持する。
- 指標は実行回数と返却文字数。キャッシュ・準備・外側レビューを含むモデルの総入力、実費、実作業全体の改善率には換算しない。

公開文書のシンボリックリンクによる別名も統合する実装を初回比較後に補い、同じ条件で8回のCLI取得を再実行して最終値を確認する。初回結果はローカルに保持し、取得条件や正解は変更しない。

新規検証は複数文書・親子節の重複排除、範囲追加、ファイル変更後の全旧範囲無効化、別reader拒否、refresh、欠落・曖昧さ・UTF-8・上限の原子的失敗、不正記録、範囲偽装、追跡済み・除外外・領域外へ解決される保存先の拒否、stdout書出し・flush失敗、保存確定失敗を含む。公開ソースの別名パスも重複せず記録を再利用できた。

今回の変更はPython補助と文書だけで、Androidの再ビルド・実端末E2Eは対象外。リモートCI、実作業での総入力・費用・手戻りの変化は未確認。モデルや設定の既定値は維持し、今回のコマンド数・文字数だけをモデル使用量の改善と扱わない。コミット・push・PR作成は行っていない。
