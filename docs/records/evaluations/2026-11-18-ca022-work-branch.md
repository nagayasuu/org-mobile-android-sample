# CA-022 作業ブランチを確定するタイミングの比較

## 比較条件

- 仮説：作業ブランチを先に作成すれば、Squash merge 後にローカルの `main` を fast-forward でき、分岐の調査と参照調整が減る。
- 条件：同じ合成ファイルの1行を編集する。対照では `main` 上でコミットしてから作業ブランチを作る。変更後は同じ基点から作業ブランチを作ってからコミットする。両条件で別々の一時リポジトリを使い、Git 2.56.0 の `git merge --squash` と別メッセージでのコミットで統合先を再現する。統合コミットを一時リポジトリ内の `origin/main` に記録する。
- 試行：対照→変更後、変更後→対照、対照→変更後の計6回。モデル呼出しや外部通信を伴わない Git コマンドの比較で、全体に30秒、各 Git 呼出しに3秒の上限を置いた。
- 成功条件：両条件で最終的に `main` が同じ内容の統合コミットを指し、作業ブランチの削除後も作業ツリーがクリーンであること。変更後の経路では参照の修復を要さず、後片付けの操作が1回以上減ること。時間は操作数とは別に観測する。

## 結果

| 条件 | 終了状態の確認 | 後片付けの Git 呼出し数 | 経過時間（3回・中央値） |
| --- | --- | --- | --- |
| コミット後に分岐 | 3/3 | 9 | 31.4、45.8、11.7 ms・31.4 ms |
| コミット前に分岐 | 3/3 | 5 | 33.1、33.9、33.4 ms・33.4 ms |

計測区間はクリーン状態の確認から作業ブランチの削除まで。状態確認、`main` への切り替え、`git merge --ff-only origin/main`、作業ブランチと統合先のツリーの一致確認、ブランチ削除を両条件で数えた。削除には一致確認後に一時リポジトリ内で `git branch -D work` を使った。対照では fast-forward が3回とも拒否された。分岐数（左右各1件）、`main` と作業ブランチの先端の一致、`main` と統合先のツリーの一致を確認し、一時リポジトリ内で `git reset --keep origin/main` を実行した。この4回が両条件の差である。

境界確認でも、同じコミットからの分岐でステージ済み・未ステージの差分と未追跡ファイルが保持された。別 worktree への新規分岐では元の場所のブランチと変更を保ち、確認済みの基点で detached HEAD から分岐できた。今回の変更作業では、開始時の `main` が取得済みの `origin/main` と同じでクリーンであることを確かめ、編集前に `docs/ca-022-work-branch` を作った。

## 判断と次の確認

[作業ブランチの確定手順](../../workflow/git.md#prepare-work-branch)を通常の変更手順へ反映した。合成比較では参照修復を省けた。時間短縮、実PRでの後片付け、全担当の使用量は未確認。保守担当が次の3件の同種作業または2026年11月末の早い方で、通常のブランチ削除に加えて分岐調査・参照調整が必要だった回数と、統合先確認から後片付け完了までの時間を見直す。
