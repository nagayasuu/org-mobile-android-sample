## 目的・計画・受け入れ条件

過去の失敗担当・圧縮・タイムアウトの usage と、上書きで消えた終了コード・時間は復元しない。今後取得できる値を確実に残すため、次の順で実装・検証した。

1. 保存器を追加し、試行・担当・attempt・試行内外・工程を識別する。失敗と途中出力、時間、元 returncode を保持し、開始と終了を別に確定する。
2. 時系列と並列時間を集約する。合計と経過窓・区間の和集合を分け、重複は拒否、未完了は null にする。モデル待ち・実費は推定しない。
3. モデルを呼ばない合成コマンドで失敗・上限・シグナル・中断再開・重複・欠測・既存 usage 集計との接続を確認する。
4. [取得範囲と実行手順](../../guides/trial-measurement.md)を正本にし、評価様式・入口と残タスクを更新する。

変更対象は `scripts/record_trial.py`、そのテスト、新しい記録手順、本記録と既存4文書の参照・状態更新。新しい監視基盤、アカウント領域の探索、追加モデル呼出し、過去の null の補完は行っていない。
