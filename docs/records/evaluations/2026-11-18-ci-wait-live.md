# 実CI待機のモデル応答・入力・検知時間の計測（2026-11-18）

## 実行前の計画

利用者の計測依頼に基づき、既存 `Android checks` run `44309405912` を2回再実行する。対象は公開リポジトリ `nagayasuu/org-mobile-android-sample` の既存コミット `a147f8c3d08365344361ae77e31bedb81fc84d3c`。未コミットの文書をCIへ送らず、コミット・push・PR投稿は行わない。

- 条件：同じ会話・主担当モデル `gpt-6.1-sol`、推論 `medium`、Codex CLI 0.166.0、gh 2.102.0。短い待機10000ms→長い待機50000msを各1回。外側 `functions.exec` は55000ms。内部の `gh run watch --compact --exit-status --interval 5` と `run_check.py --progress-interval 60 --timeout 240` は同一とする。キャッシュ・CIランナーの状態と会話の長さは完全には固定できず、一般的な改善率の実証とはしない。
- 予算：CI再実行2回、待機各240秒、各試行の待機呼出し最大24回、待機フェーズの観測総入力合計500万トークン。超過・CI失敗・計測不能では自動の追加試行を行わず、その結果と理由を残す。
- 範囲：CI再実行・計測準備・承認を試行外とし、監視起動直前の使用量スナップショットから、監視終了結果を受けた主担当が計測終了を記録するまでを試行内とする。試行中は他の調査・編集・レビュー・agent起動を行わない。経過報告は60秒以内に行い、試行内の報告に伴う応答も数える。
- 応答数：この会話の明示的なセッションログだけから `token_usage_record` の現在のthreadに属する一意な `response_id` を数える。`usage` の入力・キャッシュ入力・出力を合算し、未キャッシュ入力は入力−キャッシュ入力とする。累積usageや `token_count` を重ねて加算しない。観測モデル応答数とツール返却数を区別する。欠測・不正・矛盾する重複があれば完全な総量とはしない。
- 検知時間：監視コマンド終了を実行側で取得したUTCと、同じrun・attemptの全ジョブの最終 `completed_at` の差を測る。これは最終ジョブ終了から監視結果取得までの遅れで、GitHubのrun確定・通信・5秒の確認間隔・ツール返却を含む。runの実際の状態遷移時刻は公開APIから確定できないため、純粋なrun完了検知遅れと区別する。さらに次のモデル応答で計測終了を記録した時刻との差も別記する。同一ホストの時刻を使用し、GitHubとの時計差・秒精度の限界を残す。
- 判定：両attemptで対象SHA・成功・verify・終了コードを照合し、実モデルの応答数・入力・検知時間を取得できたかを確認する。長い側で応答数が減り、終了・失敗情報を保持し、最終ジョブからの検知が15秒以内なら手順の試行を継続する。1回ずつの差だけで既定化の効果や全工程の削減率は認定しない。
- 保存：セッション本文・個人設定・原ログは公開しない。今回の会話に対応するusageの数値・時刻と、公開CIのrun/attempt・ジョブ時刻を `.local/measurement/ci-wait-live/` に保存し、公開記録には確認した集約値だけを残す。費用は取得しない。独立レビューは試行外で行い、全作業の消費と待機フェーズの消費を混同しない。

GitHub側の基準は同じrun/attemptの全ジョブ（今回1件）の `completed_at` の最大値。APIの `total_count` と取得ジョブ数、attempt、成功、ジョブ名を照合した。run状態が `completed` へ変わった正確な瞬間は取得していないので、上表をその瞬間からの純粋な遅延とは呼ばない。GitHub時刻は秒精度で、GitHubとローカルホストの時計差も未測定。

### 準備時の停止と比較の限界

- 短い側は再実行受付から約60秒後に監視が始まった。監視コマンドの権限審査に時間を要し、ジョブの後半だけを待っている。長い側は承認後に再実行・照合・監視をまとめたため、その区間が異なる。
- 長い側の最初の照合は、再実行API受付直後の参照が期待するattempt 3を返さず、監視起動前に `AssertionError` で停止した。失敗した実行結果を保持し、同じattempt 3を再照合して監視だけを開始した。CIの再実行は計画どおり2回だけで、追加試行はしていない。この停止はusage開始スナップショットの前なので試行外。
- したがって応答数・入力・遅延の実測は得られたが、同じ長さ・開始点の待機比較にはなっていない。会話の長さやCI所要時間も変わっており、今回の差から削減率や有意な優劣を出さない。単発なので中央値の安定性やp95も主張しない。
- 50秒待機は途中の返却1回と完了返却1回だった。完了時は50秒の満了を待たず返り、最終ジョブからの結果取得は事前の15秒以内の条件を満たした。ただし応答数は同じで、応答数削減という事前条件は満たさなかった。手順は合成比較を根拠とした試行のまま維持し、実CIで削減が実証されたとは扱わない。

V1（作成agent）：実行前の入力照合は2回とも成功、入力不備による無効試行0。試行前に固定した計画と照合結果、数値だけを取得するローカル補助、各試行の開始/終了usage・ツール返却時刻・監視ログ/サマリー・GitHubのrun/jobsは `.local/measurement/ci-wait-live/` に保存した。公開前に確認した集約値のみ本書へ記載し、セッション本文・ID・ローカルパス一覧は公開しない。計画ハッシュはローカルの `input-plan.json` の対象で追跡し、実行後の結果追記を元の入力として再照合しない。
