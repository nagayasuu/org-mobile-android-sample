# CI・E2E の工程計測と待機短縮

## 目的と変更範囲

[追加候補](../../proposals/codex-adoption-remaining-tasks.md#cie2e-の完了待ちを短縮する追加案2026-11-17)のうち、利用者が除外した3（2端末並列化）以外を順に実装した。対象は工程別計測、キャッシュ、共通準備、完了検知、重複ケースの除去。アプリ本体・必須CI・ブランチ保護・アサーションは変更していない。コミット・push・GitHub Actionsの起動は行っていない。

| 項目 | 実装と維持条件 |
| --- | --- |
| 1・工程別計測 | [実行器](https://github.com/nagayasuu/org-mobile-android-sample/blob/53a0a2eda8dc087eb20ecdd87ebc3d0be3c2ab51/scripts/run_e2e.py)で設定事前テストと残りシナリオを一度ずつ実行。[run_check](../../../scripts/run_check.py)のログ・元終了コード・時間・JUnit判定を使用し、工程別に証跡を保存。Gradle `--profile` と各ケースの初期化・本体・文書作成・診断・後片付けの時間を追加。SDK導入の時間とキャッシュ命中もCI要約へ記載 |
| 2・キャッシュ | [workflow](https://github.com/nagayasuu/org-mobile-android-sample/blob/53a0a2eda8dc087eb20ecdd87ebc3d0be3c2ab51/.github/workflows/e2e.yml)でSDK platform・Build Tools・Google APIsイメージだけをキャッシュ。OS/アーキテクチャ/月/workflow内容で分離し、復元後もsdkmanagerで状態を確認。AVD・userdata・端末設定・アカウントは含めない。Gradleは作業ブランチでも保存し、同じブランチでの再利用を可能にした。新規ブランチへ共有するmain側キャッシュは統合後の手動実行で作る |
| 4・共通準備 | [E2Eテスト](https://github.com/nagayasuu/org-mobile-android-sample/blob/53a0a2eda8dc087eb20ecdd87ebc3d0be3c2ab51/app/src/androidTest/java/dev/orgmobile/reader/ReaderE2eTest.kt)の公開文書を初回選択時にだけ作成する。同じURIを更新するケースは再選択時に上書きしない。アプリ所有の残存文書の削除、URI権限解除、表示設定復元、各ケースの画像・画面階層保存を維持 |
| 5・完了検知 | 2段階E2Eを単一プロセスで待つ。CI監視の手引きは外側の固定sleepをなくし、gh監視間隔を5秒とする。60秒ごとの経過通知は完了待ち間隔ではない。元終了コードと全文ログを維持 |

## 検証と観測

対象は `084238c` からの未コミット差分。JDK 17.0.21・AGP 9.2.1・Gradle 9.4.1、専用Pixel 2/API 37・Google APIs x86_64・swangleで確認した。各コマンド・対象ファイルの内容ハッシュ・詳細ログはローカル作業記録へ保持し、公開資料には集計と判定を残す。最終E2Eで使ったDebug APKのSHA-256は `d619b33911f240be52618eb4514ccee7cb0426c6063023f626b09c0d948dbb68`。

変更前は1回の全10件、改善後は1件と9件の2回の実行であり、ビルド再利用・実行時の負荷も異なる。単発の総時間差を改善率や各案の効果として扱わない。SDK/GradleのCIキャッシュ保存・復元と5秒監視の実CI効果は未実行・未測定。GitHub Actionsの実行が可能になった段階で確認する。

## 独立レビューと後続評価

別agentがR01〜R30と実装・証跡を確認。初回に、事前summaryのXML参照が後続工程の元ファイルへ向かう問題と、証跡コピー失敗が元終了コードを上書きする問題を指摘した。保存先コピーへの参照に変更し、コピー失敗を記録しつつ元の非0終了コードを維持する修正と回帰テストを追加した。修正後の実行器7件・監視7件を確認者が独立実行し成功。さらにプロファイル一覧取得失敗時も元終了コードを維持する回帰テストを追加した。コードの修正必須指摘は解消した。最終E2Eの設定待ち失敗は原因未確定で、再確認の成功だけでは不具合解消や安定性を保証しない。原因と再発有無の確認は保守担当へ引き継ぎ、再発時は無変更リトライを重ねず診断に戻る。

採否・後続評価の担当は保守担当。[評価手順](../../maintenance/evaluation.md#codex-adoption-evaluation)に従い、同じシナリオ・環境・候補版でキャッシュ初回/再利用時を分けて複数回比較する。工程時間・キャッシュの保存/復元時間と容量・失敗率・診断の欠落・実行コスト・取得できる全担当の使用量を記録する。次の同種作業3件または2026-11-30の早い方で見直す。2端末並列化は利用者の指定により未実施。

参照：[AndroidJUnitRunnerのメソッド除外](https://developer.android.com/reference/androidx/test/runner/AndroidJUnitRunner)、[Gradleのローカルプロファイル](https://developer.android.com/build/profile-your-build)、[setup-gradle v4のキャッシュ範囲・保存元](https://github.com/gradle/actions/blob/v4/docs/setup-gradle.md)、[GitHub Actions cache v4](https://github.com/actions/cache/blob/v4/README.md)。

## マージ前の選択UI修正

[単発計測](2026-11-17-e2e-single-trial.md)で、不正UTF-8のエラー表示待ちに失敗した。保存UI階層はDocumentsUIの「1 selected」「Select」で、アプリへ戻っていなかった。`Until.newWindow()` を選択完了条件から外し、必要な選択確定操作と、選択画面の消失・アプリのルート画面表示を確認するよう変更した。

確定ボタンを押す前に、要求した文書1件だけが選択されていることを検査する。確定は一度だけとし、盲目的な再クリック・リトライや15秒上限の延長は追加しない。不正UTF-8の既存シナリオでは長押しで選択状態を作り、明示的な確定経路が実行されたことも検査する。正常選択・UTF-8エラー表示・正常文書への復帰のアサーションを維持する。

この修正は確認できた選択完了判定の不備への対応であり、夜間設定待ち失敗の原因や、負荷によって選択状態へ移った原因を確定したものではない。マージ準備時のローカルではPython147件は成功したが310.804秒を要し、E2Eは事前1件326.792秒で成功後、残り9件は1236.461秒でタイムアウトし6件失敗した。ホストの高い負荷、小さな読み取り処理の遅延・実行基盤の応答不良も観測した。これらを失敗・環境情報として保持し、時間改善の根拠にはしない。同じ環境での無変更リトライは追加せず、新しいGitHub Actions runnerで対象コミットの必須CIとE2Eを確認する。結果はPRの専用コメントへ集約する。
