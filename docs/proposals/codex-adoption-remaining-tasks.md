# Codex 導入改善の残タスク

2026-11-14時点の[導入改善メモ](codex-adoption-recommendations.md)と関連する検証記録から、継続対応が必要な4項目と改善候補を整理した。これまでの21項目に、定型処理の自動実行・失敗反復の検出・実行環境を含む回帰評価の3候補（R〜T）を追加し、既存5項目の評価範囲を具体化した。以下はタスクの記録であり、追加実験・設定変更を実施した結果ではない。

担当は保守担当とし、実行担当者・対象版・比較条件・予算は着手時に確定する。既存記録の見直し契機は、節取得改善が「次の同種開発3件または2026年11月末の早い方」、短い出力指定が「次の同種作業または2026-11-30の早い方」。自動実行・通知は設定されていない。

## 項目別の優先度と改善見込み（2026-11-14）

4つの残タスクと20の改善候補を以下にまとめる。担当は保守担当。実施状況は公開構成と過去の実行記録に基づき、完了済みの作業と残作業を分けて示す。優先度は効果の根拠・適用範囲・作業負担から判断した提案で、運用の即時変更ではない。

| 優先度 | 判定基準 |
| --- | --- |
| 高 | 入力増加・無効試行・記録喪失が観測され、既存記録やモデルを呼ばない確認から対処できる。他の比較の前提となる作業も含む。 |
| 中 | 限定条件の改善観測はあるが実作業全体への効果や追加の改善幅が未確定。前提作業の後、通常開発または予算を固定した小規模比較で確認する。 |
| 低 | 効果の定量的根拠がない、または時間増加が観測され、追加比較の負担に見合う根拠が乏しい。必要性が明確になった場合に再検討する。 |

実施状況の「部分完了」は一部の作業が完了し残作業がある状態、「未着手」は本表で提案した追加作業を開始していない状態、「保留」は再開条件または必要性の確認を待つ状態を示す。過去の関連実験が完了していても、本表のタスク全体の完了とはしない。

過去の実測は将来の期待値や保証ではない。条件付き試算も仮定が成立する場合の算術値にとどめる。欠測がある群の削減率は出さず、異なる群や重複項目の改善幅を合算しない。文字数・ビルド時間をモデルのトークン削減率へ換算しない。

## 次に進める順序

まず高優先度の項目3・B・Cをモデル呼出しなしで確認し、Aの既存記録から読取量増加の調査箇所を一つ選ぶ。その後、中優先度の項目1を、予算・停止条件・比較対象を固定した一要因比較で評価する。項目2・Dは次の同種作業の見直し時に評価し、Fは通常開発の計測に合わせて確認する。中優先度のGは対象文書と更新方法を整理したうえで文書単位に移行する。低優先度の項目4はAで探索の負担や漏れが具体化した場合、Eは長期作業で必要性が生じた場合だけ再検討する。比較のためだけに全件を繰り返さない。

検索補助・ビルドキャッシュの既存の見直し契機は「次の同種作業3件または月末の早い方」。低への分類は必要性を見直す際の順序であり、冒頭と既存記録の確認契機を取り消すものではない。

追加したHは通常開発の計測に合わせ、Iは既存の集約JSONから確認する。Jは項目2・Bの確認後に必要性と予算を判断する。K〜Pは表内の再検討条件を満たした場合だけ計画し、今回の表追加を実施の開始とはしない。CA-021（Q）も解析時間の計測で必要性を確認してから計画する。CA-002（A）の指示重複調査は既存記録から先行し、CA-007（D）のツール返却評価とCA-011（I）の表示縮約はそれぞれ独立した条件で比較する。

## 更新時の扱い

評価方法は[開発手順の正本](../maintenance/evaluation.md#codex-adoption-evaluation)に従い、結果の参照先・判断者・次の確認条件を追記して状態を更新する。元の導入改善メモで優先度「低」とした未導入の6項目はK〜Pとして追跡し、必要性の確認まで実施を保留する。既存補助の評価である項目4、標準圧縮の再評価であるEとは状態・完了条件を分ける。
