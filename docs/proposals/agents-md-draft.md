# AGENTS.md の下書き

個人開発で小さく開発フローを回すために、日常の作業で繰り返し使う指示と、詳しい手順への案内をまとめる。
この文書は検討用の下書きであり、現在の作業指示はルートの [AGENTS.md](../../AGENTS.md) に従う。

- **プロジェクトの目的**：何を実現するプロジェクトかを簡潔に示す。
- **プロジェクトの構成**：主要なコード・テスト・手順書の場所を示す。
- **現在の動作**：作業前に既存の機能がどう動くかを把握する。
- **既存の差分**：作業前に変更済みの箇所を確認する。
- **未コミット変更の保護**：既存の未コミット変更を失わないようにする。
- **今回の目標**：利用者ができるようになることを明確にする。
- **変更範囲**：今回変更する範囲を明確にする。
- **完了条件**：何を確認できれば完了とするかを定める。
- **開発サイクル**：「調査 → 最小限の実装 → 検証 → 改善」を一つの機能単位で繰り返す。
- **機能の実装単位**：入力から結果の確認まで通る最小限の機能を実装する。
- **実装の再利用**：既存の実装や標準機能を優先して使う。
- **コードの構造**：今回の変更に必要な範囲で構造を整える。
- **検証コマンド**：実際に使えるコマンドを示す。
- **ビルドの確認**：変更内容に応じてビルドが成功することを確認する。
- **テストの実行**：変更内容に応じて必要なテストを実行する。
- **主要操作の確認**：変更内容に応じて主要な利用経路の動作を確認する。
- **再発防止の確認**：不具合修正では同じ問題の再発を検出できることを確認する。
- **要件への適合**：変更が要件を満たしているかをレビューする。
- **既存機能への影響**：変更が既存機能を損なっていないかをレビューする。
- **データ保護の確認**：変更によってデータの保護が損なわれないかをレビューする。
- **不要な変更の確認**：目的と無関係な変更が含まれていないかをレビューする。
- **変更点の報告**：何を変更したかを短く報告する。
- **検証結果の報告**：実行した検証の結果を短く報告する。
- **未確認事項の報告**：確認できていない事項を明示する。
- **変更のまとまり**：Git で扱う変更を一つの目的にまとめる。
- **対象ファイルの確認**：コミットに含めるファイルを確認する。
- **差分の確認**：コミットに含める差分を確認する。
- **コミットの実行条件**：コミットを行う条件を明記する。
- **push の実行条件**：push を行う条件を明記する。
- **公開の実行条件**：公開を行う条件を明記する。
- **秘密情報の保護**：秘密情報をコミット・公開ログ・成果物に含めない。
- **ローカル専用資料の保護**：ローカル専用資料をコミット・公開ログ・成果物に含めない。
- **詳細手順の配置**：詳しい手順は別文書にまとめる。
- **詳細手順の参照条件**：どの作業でどの手順を読むかを示す。
- **指示の追加**：繰り返し起きた問題を基に必要な指示を追加する。
- **重複する規則の削除**：同じ内容を繰り返す規則を削除する。
- **古い規則の削除**：現在の作業に適さなくなった規則を削除する。

## 省略候補

上記の項目のうち、一般論の省略、作業依頼や別文書への移動、具体的な情報や参照への置き換えを検討する候補を示す。
プロジェクト固有の制約や、繰り返し起きた問題への対策は残す。Codex の動作はモデル・クライアント・設定によって変わるため、記載を省いても必ず実行されるという保証ではない。

### 基本動作と重複する一般論

- **現在の動作**：既存機能を調べるという一般論は省略し、見落としやすい仕様があれば具体的に残す。
- **既存の差分**：作業前に差分を把握するという一般論は省略候補とする。
- **未コミット変更の保護**：既存変更を失わないという基本方針は重複するため、固有の保護対象がなければ省略候補とする。
- **実装の再利用**：既存実装を優先するという一般論は省略し、使うべき共通実装があれば具体的に示す。
- **コードの構造**：必要な範囲で構造を整えるという一般論は省略し、固有の責務や依存方向があれば具体的に残す。
- **変更点の報告**：独自の報告形式がなければ、通常の完了報告に任せる。
- **検証結果の報告**：独自の記録形式がなければ、通常の完了報告に任せる。
- **未確認事項の報告**：独自の報告要件がなければ、通常の完了報告に任せる。

### 作業ごとの依頼へ移す項目

- **今回の目標**：作業ごとに変わる具体的な目標は、その作業の依頼文や計画に記載する。
- **変更範囲**：作業ごとに変わる具体的な対象範囲は、その作業の依頼文や計画に記載する。

### 詳細手順への参照にまとめる項目

- **要件への適合**：一般的なレビュー観点の列挙は、実施条件を含むレビュー手順への参照にまとめる。
- **既存機能への影響**：一般的な回帰確認の指示は、対象と確認方法を定めたレビュー手順への参照にまとめる。
- **データ保護の確認**：一般的な安全確認の指示は、固有の保護対象を定めたレビュー手順への参照にまとめる。
- **不要な変更の確認**：一般的な差分確認の指示は、レビュー手順への参照にまとめる。
- **対象ファイルの確認**：コミット対象の選び方は、Git 運用規約への参照にまとめる。
- **差分の確認**：コミット前の差分確認は、Git 運用規約への参照にまとめる。

### 具体的な情報に置き換える項目

- **プロジェクトの目的**：「目的を示す」という作成者向けの説明は、実際の目的や README への参照に置き換える。
- **プロジェクトの構成**：「場所を示す」という作成者向けの説明は、実際の配置や構成資料への参照に置き換える。

### 指示書の保守用チェックリストへ移す項目

- **詳細手順の配置**：文書の分割方針は、指示書を作成・更新するときのチェックリストへ移す。
- **指示の追加**：繰り返した問題を規則に反映する方針は、指示書の更新用チェックリストへ移す。
- **重複する規則の削除**：重複の整理は、指示書の更新用チェックリストへ移す。
- **古い規則の削除**：古い規則の見直しは、指示書の更新用チェックリストへ移す。
