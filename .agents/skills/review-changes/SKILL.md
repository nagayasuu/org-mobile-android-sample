# 変更をレビューする

リポジトリのルートを作業ディレクトリとし、[AGENTS.md](../../../AGENTS.md)に従う。
[開発手順の agent レビュー](../../../docs/development-workflow.md#agent-review)を実行し、[Git 運用規約](../../../docs/git-workflow.md)を守る。
[作業に応じた読み方](../../../docs/development-workflow.md#workflow-reading)で必要な範囲を選び、依頼・返答は[agent の入力と出力を絞る](../../../docs/development-workflow.md#agent-context)に従う。

- 目的・受け入れ条件、比較元と先の SHA または未コミット差分を固定する。作業状態、対象の履歴、未追跡ファイルも確認し、既存の無関係な変更やローカル専用資料を対象へ含めない。
- 作成者が自身の変更を確認する場合は、利用できれば別のレビュー agent に対象と既知の未確認事項を渡す。利用できなければセルフレビューと制約を記録する。レビュー担当として依頼を受けた agent は対象を直接確認する。
- 依頼には会話全体や生ログを転記せず、正本の依頼文に必要な情報と根拠の参照先をそろえる。再レビューでは更新差分と影響する ID を再確認し、引き継ぐ ID の根拠が引き続き有効かを確かめる。
- 作成者の説明だけで判定せず、差分、関連する公開文書・コード・設定、必要な公式資料と実行結果を照合する。[変更に合う検証](../../../docs/android-build.md)を選び、他者による実行結果の参照と、自身の実行を区別する。
- [R01〜R30](../../../docs/development-workflow.md#review-checklist)を全件判定する。項目の本文は正本から読み、各 ID に「確認済み・対象外・未確認・要修正」と根拠または理由を付ける。同じ判定と根拠の ID だけをまとめる。
- レビュー担当は対象ファイルを修正せず、指摘と再確認を分ける。対象が更新された場合は版を固定し直し、影響する項目を再確認する。
- [PR テンプレート](../../../.github/pull_request_template.md)の「レビュー記録」「指摘と残るリスク」に合わせて結果を返す。PR がなければ作業メモまたは完了報告へ残す。修正必須の指摘、残るリスク、未確認の理由と次の確認方法、採用可・要修正・未確認のため保留の判定を記す。

公開可能な根拠だけを残す。レビュー依頼だけでコメント投稿、GitHub の承認、コミット、push、マージをしない。agent の判定は必須 CI や E2E の実行を代替しない。
