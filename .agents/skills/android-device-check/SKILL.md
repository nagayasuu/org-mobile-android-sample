# Android 端末で確認する

リポジトリのルートを作業ディレクトリとし、[AGENTS.md](../../../AGENTS.md)に従う。
操作と記録の正本は[端末確認手順](../../../docs/device-testing.md)。環境・成果物は[ビルド・検証の手引き](../../../docs/android-build.md)で確認する。

1. 変更の受け入れ条件、対象コミット、APK の取得元と SHA-256、端末・OS を対応付ける。成功した CI run の APK を優先し、ローカル版や異なる環境を使った場合は違いを記録する。
2. 利用できる端末操作ツールと接続・認可状態を確認する。複数端末では対象を特定する。接続できなければ理由と次の確認方法を残し、準備や手順の提示を実機確認の成功としない。`android-cli` skill は補助に使えるが必須にせず、正本の `adb` 手順でも進める。
3. APK を導入・起動し、正本のスモークテストと変更に必要な追加確認を行う。公開サンプル・合成データだけを使い、私的な文書を開いたり画面取得したりしない。署名不一致によるアプリ削除は状態と URI 権限の喪失を伴うため、対象と実行許可を確かめる。
4. UI 変更では[アクセシビリティの確認方針](../../../docs/development-workflow.md#アクセシビリティを設計確認する)に従い、対象の主要操作を確認する。画面取得や UI 構造だけで TalkBack の操作確認済みとはしない。
5. 正本の記録形式で、実行した操作、期待結果・実際の結果、実行者、省略した操作を整理する。Dropbox 経由、実機、CI APK の確認をそれぞれ区別する。
6. 変更した端末設定を元に戻す。追加データを片付ける場合は対象を限定し、既存の文書は削除しない。

端末識別子、個人のファイル名・内容・URI、画面画像・構造などのローカル専用情報を公開レポートへ含めない。性能を評価するときは[性能計測の方針](../../../docs/development-workflow.md#性能計測の対象と方法)も使い、スモークテストの成功と時間・メモリの計測結果を区別する。
